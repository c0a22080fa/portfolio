## 背景と問い

研究で使う言語モデルの「中身」を理解したくて、モデルの内部を調べた論文を1本ずつ自分の手で再現しています。1本目に選んだのは、Nanda らの *Progress measures for grokking via mechanistic interpretability*（ICLR 2023）です。

grokking とは、練習問題はすぐ解けるようになるのに、見たことのない問題が解けるようになるのはずっと後になる、という現象です。論文が実際に何を測っていて、何がまだ分かっていないのかを確かめることを目的にしました。

## 進め方

1本の論文を「読む → 実装する → 実行する → 結果を見る → まとめる」の5段階で進めると決め、テンプレートにしています。

1. 公式コードを書き換えずに動かし、論文の主な結果が出るかを確かめた（1本）
2. 自作のコードで課題の構造を変え（普通の足し算、2つの時計、正59角形の回転と裏返し、でたらめな表）、モデルの中にできる形を比べた（5本）
3. 論文と同じデータの分け方に、抜け道があることに気づいた
4. 分け方を直して、課題と練習量（30〜60%）を変えて学習し直した（34本）

## 見つけた抜け道

足し算は順番を入れ替えても答えが同じです。ところが論文と同じ分け方だと、「3+5」が練習用に、「5+3」がテスト用に入ることがありました。これでは、テスト用の問題の答えを実質的に練習で見ていることになります。

調べると、テスト用の約3割で、入れ替えた問題が練習用に入っていました。抜け道をなくすと、練習用30%ではどの課題も50,000エポックまでに解けませんでした。

## まだ分かっていないこと

数字が時計のように並ぶことは確かめられましたが、モデルが本当にその時計を使って答えを出しているかは、自作のコードではまだ確かめていません。結果と考察は、「数字で確かめた」「目で見ただけ」「まだ確かめていない」と、確からしさの度合いを分けて書いています。

## 環境と成果物

- ARM の GPU サーバー1台。50,000エポックの学習1本が2.5〜23分程度
- NVIDIA の PyTorch イメージに必要なライブラリと日本語フォントを足した Docker イメージ
- 発表スライド（本編26枚・付録12枚）と、出てきた言葉をかみくだいた用語集（30語）も公開しています
